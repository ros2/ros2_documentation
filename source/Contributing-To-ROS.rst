Contributing to ROS
=========

**Area: Community, Contributing, | Content-type: about | Experience: beginner, intermediate, advanced**

.. contents:: Table of Contents
   :local:

ROS is an open source set of tools and libraries and contributors are an important part of our community. Whether you are a developer, researcher, company, or student, contributing to our open source software helps us to grow and improve. Thanks to the contributions of our community members, it is easy to share code, exchange ideas, and work together on projects.

This page presents the ways in which you can contribute to ROS.

Your first contribution
-----------------------
ROS makes it easy to contribute, and anyone can participate. Depending on your skills and experience, you can review and update the ROS documentation, contribute code, or fix bugs.

For example, if you are a complete beginner, you could start with some beginner tutorials, checking them for accuracy as you work through the tasks. If you are a developer familiar with ROS,you could try fixing bugs, or suggesting improvements.

Writing and updating documentation 
----------------------------------

Contributing to ROS documentation is a great way to learn about and improve ROS, and anyone can take take part. Writing and updating documentation ensures it stays aligned with the code. Whenever the code is updated, the documentation should be updated alongside it so it remains accurate and reliable. If you are a beginner, you can help by fixing small issues such as typos or unclear instructions, while more experienced contributors can improve and expand documentation for complex features.

Testing and reviewing documentation
-----------------------------------

Testing and reviewing documentation makes sure it is clear, accurate, and easy to follow in practice. It involves checking that instructions work as expected and reflect how the code behaves. If you are a beginner, you can follow our tutorials and how-to guides and report anything that is unclear or incorrect. If you are a more experienced contributor, you can validate technical accuracy, identify gaps, and improve the overall structure and clarity.

Ready to get started? 

* Follow your first tutorial, and review the instructions as you go: <link to easy tutorial> 

* Follow your first how-to guide and review the instructions as you go: <link to easy how-to guide> 

Contributing to code
--------------------

Contributing to code involves reviewing an existing project and making improvements such as fixing bugs or adding features. These changes are submitted through a pull request (PR)so they can be merged into the shared codebase. Pull requests are reviewed for quality and correctness before any changes are merged.

Anyone can contribute to our open source code. If you are a complete beginner looking for an entry point, start with a simple contribution such as fixing a small mistake. If you are a more experienced developer, consider contributing at a deeper level by designing new features, reviewing code from other developers, or fixing complex bugs.

Reviewing a PR
--------------

Reviewing a PR involves carefully checking proposed changes to make sure they are correct, well written, and do not introduce issues. Anyone can review a PR. If you are a beginner, it is a great way to learn the codebase and ask questions where something is unclear. If you are a more experienced developer, you can contribute by identifying performance or security issues and ensuring overall code quality.

Reporting a bug
---------------

Reporting bugs involves identifying and describing problems in the software so they can be understood and fixed. If you are a beginner, you can report issues you encounter, for example, when following a tutorial, and include the steps needed to reproduce the problem. If you are a more experienced contributor, you can provide detailed technical information to help developers quickly diagnose and resolve the issue.

Ready to get started?

* Report your first bug: <link to how-to report a bug>

Triaging a bug
--------------

Triaging a bug involves reviewing reported issues to understand the problem, assess its impact, and decide what action to take next. If you are a beginner, you can help by checking whether an issue can be reproduced and providing additional details where needed. If you are a more experienced contributor, you can prioritise issues, identify root causes, and guide how and when they should be resolved.

Ready to get started?

* Follow our tutorial on how to assess and prioritise bugs: <link to tutorial>

* Triage your first bug: <link to guidelines on triaging a bug>
  
* Review reported issues and check if they can be reproduced: <link to bug list>

Running tests
-----------------

Running tests involves checking that the code behaves as expected and that recent changes have not introduced issues. If you are a beginner, you can run existing tests and report any bugs you find. If you are a more experienced developer, you can investigate failures, improve test coverage, and add new tests.

Ready to get started?

* Follow our testing guide to learn how to run and interpret test results: <link to testing guide > 
  
* Report a bug you found during testing: <link to how to report a bug>

----------------------------------

Reporting security vulnerabilities involves responsibly identifying and disclosing potential security issues so they can be safely addressed and resolved.
