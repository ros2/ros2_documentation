Contributing to ROS
=========

ROS (Robot Operating System) is an open-source ecosystem. Contributions from the ROS community helps us to grow and improve. 
This article introduces the ways in which you can contribute to ROS.

Contribute to ROS development
-----------------------------

Anyone can contribute to the development of ROS. If you are a complete beginner looking for an entry point, start with a simple contribution such as fixing a small issue. If you are a more experienced developer, consider contributing at a deeper level by designing new features, reviewing code from other developers, or fixing complex issues.

Contribute to code
~~~~~~~~~~~~~~~~~~

 Contributing to our open source involves reviewing an existing project and making improvements such as fixing issues or developing features. Choosing an issue from the list of code issues is a great way to get started with contributing to ROS.

Ready to contribute?

* Pick an issue and submit your first pull request: <link to how-to article: making a pull request> 
  
* Learn about the tech stack we use: <link to tech stack topic>

Review a pull request
~~~~~~~~~~~~~~~~~~~~~

Reviewing a pull request involves carefully checking proposed changes to make sure they are correct, well written, and do not introduce issues. Anyone can review a pull request. If you are a beginner, reviewing a pull request is a great way to learn the codebase and ask questions where something is unclear. If you are a more experienced developer, you can contribute by identifying performance or security issues and ensuring overall code quality.

Ready to contribute?
  
* Review your first pull request <link to how-to article: reviewing a pull request>

Contribute to ROS quality assurance
-----------------------------------

Report an issue
~~~~~~~~~~~~~~~

Reporting issues involves identifying and describing problems in the software so they can be understood and fixed. If you are a beginner, you can report issues you encounter, for example, when following a tutorial, and include the steps needed to reproduce the problem. If you are a more experienced contributor, you can provide detailed technical information to help developers quickly diagnose and resolve the issue.

Ready to contribute?

* Report your first issue <link to how-to article: Reporting an issue> 

Triage an issue
~~~~~~~~~~~~~~~

Triaging an issue involves reviewing reported issues to understand the problem, assess its impact, and decide what action to take next. If you are a beginner, you can help by checking whether an issue can be reproduced and providing additional details where needed. If you are a more experienced contributor, you can prioritise issues, identify root causes, and guide how and when they should be resolved.

Ready to contribute?

* Pick an issue to triage

* Triage your first issue: <link to how-to article: Triaging an issue>

Report security vulnerabilities
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Reporting security vulnerabilities involves responsibly identifying and disclosing potential security issues so they can be safely addressed and resolved. 

If you spot a security vulnerability, contact ros@osrfoundation.org

Become a core maintainer
~~~~~~~~~~~~~~~~~~~~~~~~

ROS maintainers ensure that the project is generally making progress. The responsibilities of maintainers include:

* Reviewing incoming code contributions for style, quality, and overall fit into the goals of the repository and ROS

* Ensuring that CI continues to stay green

* Merging pull requests that meet the quality and CI standards above

* Addressing issues opened up by users

A core maintainer is responsible for guiding development, reviewing contributions, and helping ensure the quality and direction of ROS. At ROS, there are maintainer roles: as a Committer or a PMC Member. A committer can directly contribute code, while a Project Management Committee (PMC) member helps guide the overall direction and governance of the project.

Ready to contribute?

* Become a core maintainer: <..\How-To-Guides\Core-maintainer-guide.rst>_

Contribute to documentation
---------------------------

Write and update documentation 
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Contributing to ROS documentation is a great way to learn about and improve ROS, and anyone can take part. Writing and updating documentation ensures it stays aligned with the code. Whenever you update the code, you should also the documentation so it remains accurate and reliable. If you are a beginner, you can help by fixing small issues such as typos or unclear instructions, while more experienced contributors can improve and expand documentation for complex features.

Ready to contribute?

* Read our documentation contribution guidelines: <link to guidelines>

* Browse the documentation issue list, and choose an issue to fix: <link to issue list>

* Learn about the documentation tools we use: <link to documentation tools topic>

Test and review documentation
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Testing and reviewing documentation makes sure it is clear, accurate, and easy to follow in practice. It involves checking that instructions work as expected and reflect how the code behaves. If you are a beginner, you can follow our tutorials and how-to guides and report anything that is unclear or incorrect. If you are a more experienced contributor, you can validate technical accuracy, identify gaps, and improve the overall structure and clarity.

Ready to contribute?

* Follow a tutorial, how-to guide or other documentation  

* If you spot something inaccurate or unclear provide your feedback: <link to report an issue or issue (to be made)> 

Provide support
---------------

ROS users come from a wide range of technical backgrounds and use different operating systems. Some are completely new to ROS, so even those with a little experience can play an important role in supporting others as they get started.

If you notice a question on Robotics Stack Exchange that relates to an issue you have encountered, consider sharing what worked for you. If you aren't entirely sure your answer is correct, just say so. The community is there to help, and others will step in to clarify or add more detail if needed.

Ready to contribute?

* Support others with working through our tutorials, starting with First steps with ROS <link to first steps with ROS>
  
* Provide pointers on Stack exchange: <link to stack exchange> 

* Chat with new community members by visiting the official Open Robotics Discourse https://discourse.openrobotics.org/c/ros/111
